# 医疗多智能体推理

## 核心工作流

1. 区分用户已提供的事实、检索证据、模型推断和仍缺失的信息，不补写患者事实。
2. 将复杂问题拆成互补子问题，并把每个子问题分配给专业最匹配的专家。
3. 要求专家说明结论所依据的证据、适用条件、反例和不确定性。
4. 汇总时检查覆盖范围、专家一致意见、冲突和证据缺口；不得用简单多数票掩盖高风险分歧。
5. 在最终回答前执行安全检查，明确紧急风险、禁忌、需要补充的信息和就医升级条件。
6. 给出直接回应用户问题的结论，同时说明系统边界；避免把一般医学信息表述为个体化确诊或处方。

## 脑卒中专家路由

当问题涉及脑梗死、脑出血、短暂性脑缺血发作、蛛网膜下腔出血、
脑静脉系统血栓或卒中后管理时，按
[脑卒中固定专家库与路由](references/stroke-expert-roster.md)
选择固定名称的专家并执行对应角色卡。非卒中问题不要强行套用卒中专家库。

## 证据与分歧

按 [references/evidence-and-consensus.md](references/evidence-and-consensus.md) 处理检索证据、证据冲突、专家分歧和可追溯性。

## 安全与升级

按 [references/safety-and-escalation.md](references/safety-and-escalation.md) 执行红旗检查、风险分层和安全输出。

## 技能进化边界

- 只进化可复用的流程、检查清单和表达约束。
- 不从单个病例提炼疾病事实、药物剂量、诊断阈值或治疗方案。
- 只有来自脱敏且经人工审核的失败记录才能用于生成候选技能。
- 候选技能必须通过固定验证集和人工批准，不能从离线任务自动发布到在线系统。
